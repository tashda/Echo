Hatch

The design for the new Labs. Every screen, state, workflow and name, with sample data. Where there is a choice to make, you will find the options, my recommendation and the reason, and a place to answer.

The app does the bookkeepingStatuses, GitHub labels, SQLite and the sync record change in one app function. Agents call hatch, they never edit state.
Every status says whose turn it isYou, an agent, or Hatch itself. The Desk shows only what waits for you.
Look first, build laterSketches are HTML and cost seconds. Swift specimens come once a direction is picked.

Tell me in the chat when you have left notes or questions and I will read them, answer them here under your question, and change the options if you ask for it. Names, ticket types and statuses

The vocabulary comes first because every screen uses it. "Round" is replaced by clearer words, and every status carries a colour for whose turn it is.

Ticket types

Question

Use it for an idea or UX issue that is still words.
You get a reply that has read the Spec and related tickets, with a recommendation.
Ends answered, often with new tickets linked.

Sketch

Use it for exploring a layout or flow before any Swift.
You get 2 to 4 variants as HTML, side by side, with pinned comments.
Ends a direction chosen. "Make it real" creates a Proposal.

Proposal

Use it for a specific change you want to see in Swift, with several options. This replaces today's Round.
You get specimens with controls and scenarios, judged against Echo today.
Ends an accepted option goes to Build.

Tweak

Use it for a small change with one obvious fix.
You get no judging step. It is checked against the Spec, built, and shown in a Preview.
Ends merged after you verify.

Bug

Use it for something in Echo that behaves wrongly. Needs steps, expected, actual.
You get one fix straight to Build, or an upgrade to a Proposal when there are several fixes.

Theme

Use it for grouping related tickets, like "Connection management".
You get a parent with progress (3 of 7 done) and its children listed.

Data, sync and the agent contract

SQLite is the local database with proper indexes and full-text search. GitHub Issues in a private repo hold the tickets. Hatch syncs them with code, and every sync is recorded. Agents talk to Hatch through one command and never edit state.

The hatch command agents use

Each command validates the move, writes SQLite and GitHub, records the sync, and answers with the exact next step. An agent never has to remember a procedure.

CommandWhat it doesReturns
hatch nextWhich ticket should I take?The ticket and its type of work
hatch take #151Claim the ticket, create the workspaceBrief: ticket, answers, related, Spec items, rules for this type
hatch ask #151 "…"Ask you a question (structured)Status moves to Needs answers
hatch offer #151Hand in options or variantsHatch builds the Stage, runs the quality gate, then Your call. A failed build goes back to the agent.
